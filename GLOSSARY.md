# Glossary

- **Repository**: A project folder whose files and complete change history are tracked by Git.
- **Commit**: A saved snapshot of the staged changes, with a message describing what changed.
- **Branch**: A movable pointer to a line of commits, letting me work on a change separately from `main`.
- **HEAD**: A pointer to the commit (usually the tip of the current branch) that I currently have checked out.
- **Staging area**: The place (the index) where I collect the changes that will go into the next commit.
- **Remote**: A version of the repository hosted elsewhere, such as on GitHub, that I can push to and pull from.
- **Origin**: The default name Git gives to the remote I cloned from or first connected to.
- **Clone**: A full copy of a remote repository, including its history, made on my own machine.
- **Fork**: My own copy of someone else's repository on GitHub, where I can make changes without affecting the original.
- **Merge conflict**: A situation where Git cannot combine two branches automatically because both changed the same lines, so I must choose the result.
- **Pull request**: A GitHub request asking for my branch's changes to be reviewed, discussed and merged into another branch.
- **Tag**: A fixed, named label (such as `v1.0`) on a specific commit, often used to mark a release.
